  Postgres only runs initdb when the data dir is EMPTY.
  A leftover dir from a previous install means Postgres boots
  with OLD credentials — even if the Secret is correct.

  Verify after every install:
    kubectl exec -n {{ .Release.Namespace }} deploy/{{ include "blooger.db.name" . }} -- \
      psql -U postgres -c "\du"
  → {{ .Values.db.auth.username }} must appear in the list.

{{- if eq .Values.db.persistence.mode "hostPath" }}

  ⚠  hostPath dirs are NOT removed by Helm. Reinstalling without
  wiping = stale credentials = broken backend. Always:

  1) Note the DB node:
       kubectl get pod -n {{ .Release.Namespace }} \
         -l app.kubernetes.io/name={{ include "blooger.db.name" . }} -o wide

  2) Uninstall:
       helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}
       kubectl delete namespace {{ .Release.Namespace }}

  3) Wipe data dir on that node —
     kind / single-node:
       docker exec -it <node-name> rm -rf {{ .Values.db.persistence.hostPath.path }}
     cloud cluster:
       kubectl debug node/<node-name> -it --image=busybox -- \
         sh -c "rm -rf /host{{ .Values.db.persistence.hostPath.path }}"

  4) Reinstall (Postgres re-inits with fresh credentials):
       helm install {{ .Release.Name }} oci://ghcr.io/githubak2002/charts/blooger \
         --version {{ .Chart.Version }} \
         --namespace {{ .Release.Namespace }} --create-namespace
{{- else }}

  helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}

{{- end }}
